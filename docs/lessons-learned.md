# 调试与踩坑复盘

这份文档不按提交时间罗列修改，而是总结本项目中最值得复用的工程经验：观察到了什么、错误假设是什么、如何定位，以及下一版应该如何避免。

## 1. 阻塞式主循环无法提供可靠的控制周期

### 现象

控制、串口打印、传感器处理和调试命令都放在主循环时，PID 实际采样间隔会随 I/O 耗时变化。即使平均循环频率接近目标，周期抖动仍会改变积分和微分项的行为。

### 定位

将问题从“PID 参数不对”拆为两部分：控制算法本身，以及算法运行的时间基准。检查代码后发现阻塞延时和可变长度通信路径参与了控制节拍。

### 处理

将 V3F 控制链迁移到 TIM2 固定节拍，内环约 150 Hz、外环约 75 Hz；V5F 使用 tick 风格的非阻塞调度，传感器数据按各自到达节奏更新。当前 V5F 的 SysTick1 初始化是赛后为修复链接和中断入口新增的代码，尚未上板复验。

### 仍需改进

固定中断只解决触发周期，不自动保证执行时间。下一版应测量 ISR 最大执行时间、占空比和抢占关系，并尽量让中断只触发控制任务或处理最小必要逻辑。

## 2. “收到光流数据”不等于“可以闭环使用”

### 现象

光流原始量能够持续更新，但接入闭环后可能出现方向错误、静止漂移或速度反馈与实际运动不一致。

### 根因类别

- 模块 X/Y 轴、机体前/右方向和 Roll/Pitch 控制方向没有统一。
- 光流速度与距离、倾角及模块内部算法模式相关。
- 静止时仍存在零偏和积分漂移。
- 质量低、距离无效或旧帧仍可能表现为“变量里有数值”。

### 处理

增加坐标轴映射、质量阈值、更新时间检查、解锁前零偏估计、静止检测和诊断计数；针对两种实现保留版本快照进行对比，最终恢复更完整的预回滚方案。

### 教训

传感器接口至少应包含数值、单位、坐标系、采样时间、有效性和故障语义。只传两个速度数值会把真实问题推迟到控制器里暴露。

## 3. 跨核结构体不是普通全局变量

### 风险

V5F 写、V3F 读同一段 SRAM。两侧只要字段顺序、对齐或类型有一处不一致，后续字段就可能全部被错误解释。即使定义相同，读取多个字段期间写方也可能正在更新。

### 当前处理

- 两个核心保持同名、同布局的 `SharedSensorData_t`。
- 使用固定 SRAM 地址映射。
- 为部分关键数据维护更新计数、帧标记和时间戳。
- TOF 已有 commit-marker + 读侧双检；光流/XYKF 有 marker/timeout，但通用 IMU 仍缺少独立 freshness failsafe。

### 下一版方案

从单一协议定义生成两侧头文件，加入结构大小和字段偏移静态断言；采用序列锁或双缓冲发布完整快照，并明确内存屏障与缓存策略。

## 4. 混控符号错误比 PID 参数错误更危险

### 现象

姿态向某方向偏转时，如果对应电机修正方向相反，闭环会形成正反馈。此时继续增大 PID 参数只会更快失控。

### 调试方法

1. 拆桨并固定机架。
2. 分别验证四个逻辑电机与物理电机的映射。
3. 人工倾斜每个轴，观察控制修正符号而不是先观察“能否起飞”。
4. 用单电机模式核对 PWM 通道。
5. 只有符号、顺序和旋向全部确认后才讨论参数整定。

### 教训

控制问题的排查顺序应是执行器映射、反馈符号、传感器坐标、时间基准，最后才是增益。否则调参会掩盖结构性错误。

## 5. 高度控制必须定义数据消失时发生什么

### 问题

距离传感器可能返回哨兵值、超量程、异常方向或停止更新。如果控制器继续积分，数据恢复时可能出现很大的油门突变。

### 当前处理

- 对距离范围和状态进行验证。
- 使用 Roll/Pitch 倾斜补偿得到近似垂直高度。
- 通过连续样本确认、低通滤波和更新时间维护高度估计。
- 短时冻结时停止积分；超时后标记无效并进入降级路径。
- 重新进入控制前检查高度、垂直速度、油门余量和连续有效帧。

### 教训

闭环模式必须同时设计进入条件、保持条件、退出条件和重新进入条件。只有 `enable` 标志而没有故障状态机的控制器是不完整的。

## 6. 在线调参需要与安全边界分离

### 收益

VOFA Commander 允许在不反复编译烧录的情况下改变增益、遥测视图和发送频率，大幅缩短观察—假设—验证循环。

### 风险

如果所有参数在 armed 状态下都可任意修改，拼写错误、量纲误解或串口脏数据可能直接改变危险输出。

### 当前事实

- 高度参数等一部分命令有 disarmed 条件和数值范围。
- 部分 PID/姿态增益仍可直接写入，`strtof()` 也没有统一拒绝 NaN/Inf/非法尾部；这是尚未关闭的行为风险。
- PID 输出、总距和 PWM 层仍保留独立限幅，但下游限幅不能替代命令输入校验。
- 遥测发送与控制计算解耦；赛后增加 queue drop/overflow counters，便于判断高频输出是否丢帧。

### 下一版方案

为命令定义版本、范围、校验和返回状态；把运行时安全参数与实验参数分组，并记录每次试验的配置快照。

## 7. 回滚需要证据，而不是凭感觉

光流实现曾经历回滚与恢复。单纯切回“之前能用的版本”会丢失问题上下文，因此项目保留了回滚前后的代码快照和差异说明，用于确认变化涉及速度源、坐标映射、零偏、位置原点与遥控接管逻辑。

更理想的方式是为每次实验保存：固件 commit、硬件配置、参数、输入数据、现象和结论。这样回滚才能成为受控实验，而不是版本猜谜。

## 如果重新开始

下一版会优先完成以下基础设施，再扩展自主功能：

1. 建立明确的信号命名、单位和坐标系文档。
2. 为共享协议生成单一来源定义和一致性检查。
3. 测量控制任务执行时间与调度抖动。
4. 建立拆桨故障注入清单和可重复的台架日志格式。
5. 将模式状态机、控制器、命令解析和遥测从大文件中拆分。
6. 用可回放的传感器日志验证数据门控与控制切换。

比赛结果结束了项目周期，但这些问题和解决路径仍然能够反映真实的嵌入式系统工程能力。
